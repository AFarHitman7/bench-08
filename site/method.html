Method & caveats

What this is, and what it is not.

A small benchmark of one-shot creative and technical work. Eight tasks, two variants, one model per run. The caveats are part of the result.

The shape of the test

Each run received the same sixteen prompts: eight tasks, each in a thin variant (intent only) and a thick variant (a full brief with audience, constraints and success criteria).

Subagents were asked to return exactly one self-contained file. No network requests, no external images or libraries, no build step. The orchestrator collected the reply and saved it.

The tasks are deliberately different: visual composition, interface design, critique, motion, explanation, fiction, implementation and code review. There is no single score that makes sense across all eight.

Creative work is therefore presented without a number. The parser and code-review tasks carry a short technical note because those tasks have verifiable failure modes.

The eight tasks

TaskFormatBrief
01 Poster SVG The Last Ferry, 11:40pm — a poster for a crossing between San Remo and the island of Vell. Two inks, one paper tone, a condensed grotesque and a monospace timetable.
02 Interface HTML Inkwell — photograph a page of handwriting, get clean LaTeX back. The hero must show a handwritten page beside its rendered output.
03 Critique HTML A shipped landing page is supplied as a fixture. Find the five most damaging problems, repair them, and record what changed in a note of at most 150 words.
04 Motion HTML A title card for a short film about a night ferry crossing. The word must rest legibly for at least two seconds, and the loop seam must be invisible.
05 Explanation Markdown Cover the problem DNS solves, what happens between typing an address and the page appearing, why answers are remembered, and what usually goes wrong.
06 Fiction Markdown A workplace after hours, third person, one character. The clock must earn its place: something in the story depends on it.
07 Build MJS parseDuration("1h30m") returns seconds. It accepts h, m and s in any order, rejects invalid input with TypeError, and runs its own tests with node:test.
08 Code review Markdown The fixture is a small keyed limiter. The thick version asks for severity, location, problem, why it matters and a direction, in at most eight findings.

What we checked

  • Every expected artifact exists and parses as its declared format.
  • SVG dimensions, HTML self-containment, non-empty MJS and Markdown.
  • Both build tasks run their own tests with node --test; all saved tests pass.
  • Word counts for the 100-word story and the 150-word explainer; note length on the critique.
  • Technical notes on the two code tasks: whether the review found the planted defects, and whether the parser meets its brief.
  • No subagent read another task’s output; no artifact contains an external URL.

Limitations

  • Not a leaderboard. These are eight runs, not a statistically meaningful sample. One run per model except Claude Haiku 5.5 and Muse Spark 1.3.
  • Two runs are not comparable. Muse Spark’s saved files were trimmed and, in run 2, not disclosed. They are included for transparency, with a “Not comparable” badge.
  • Process differs. DeepSeek’s subagents used a browser and wrote working files; GPT’s loaded skills. Those runs are marked as caveats, not hidden.
  • Creative work is unscored. Posters, interfaces, motion, fiction and critique are shown as submitted. The absence of a score is deliberate, not an oversight.

A note on labels

Every card names the model and the run.

Claude Haiku 5.5 and Muse Spark 1.3 have two runs each. The run badge is part of the result, not a detail to ignore.

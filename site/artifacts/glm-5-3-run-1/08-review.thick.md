[blocker] prune — the guard reads `hits[0] < t - windowMs`, but `allow` stores `{ key, time }` objects, so the object coerces to NaN, the comparison is always false, and nothing is ever pruned — once a key reaches `limit` hits it is denied forever and the `hits` array grows without bound, turning the limiter into a permanent counter with a memory leak — compare against the stored timestamp: `hits[0].time < t - windowMs`
[blocker] reset — splicing at `i` inside a forward loop skips the entry that shifts into slot `i`, so consecutive same-key entries survive (`[A, A, A]` leaves one `A` behind) — reset silently fails on exactly the repeated-key pattern this limiter produces, and since prune never removes anything the leftovers keep the key throttled despite an explicit reset — iterate backwards from `hits.length - 1`, decrement `i` after each splice, or rebuild the array with `filter`
[major] allow — `hits.filter(h => h.key === key)` scans every stored hit of every key on every call, denials included — per-call cost is O(total hits), so the limiter gets slower as overall traffic grows instead of staying proportional to the single key being checked — bucket hits per key (e.g. a `Map` from key to that key's own timestamps) so `allow` only touches its own bucket
[minor] createLimiter — `limit <= 0` makes `allow` deny unconditionally, and `windowMs <= 0` (once prune works) degenerates the window, with no error at construction — a silent misconfiguration produces a limiter doing the opposite of its job, which is hard to spot in production traffic — validate at construction: throw, or clamp with a warning, on non-positive or non-finite `limit` and `windowMs`
[minor] prune — `hits.shift()` inside the while loop is O(n) per removal, so draining a large backlog is O(n²) — a burst that floods the window stalls the next `allow` call at exactly the moment traffic is heaviest — remove from the end with `pop`, or keep a start index and drop the stale prefix in one splice
[minor] reset — calling it without an argument silently matches entries keyed `undefined`, and there is no way to clear all keys at once — a missing argument fails silently, and callers cannot reinitialize shared state (tests, reconfig, shutdown) — accept a no-argument form that clears everything, or throw when `key` is omitted or `undefined`
[minor] module (tests) — the injectable `now` exists precisely to make time behavior testable, but nothing exercises expiry past `windowMs`, denial at exactly `limit`, or `reset` over back-to-back same-key hits — both blockers above would pass a casual smoke test, so nothing will catch them before production — add fake-clock tests: expire a hit just past `windowMs`, deny the `limit + 1`-th call, then reset a key with consecutive hits and assert it is empty
[nit] prune — a hit exactly `windowMs` old is kept (`<`, not `<=`), so the effective window is closed on the old edge and that boundary is undocumented — an off-by-one window is invisible until someone tunes `windowMs` against an external quota and the counts differ by one — state the interval in a comment, or switch to `<=` if the intent is "drop strictly older than the window"

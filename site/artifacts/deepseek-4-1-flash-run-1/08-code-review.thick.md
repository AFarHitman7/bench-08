[blocker] `reset` loop, lines 17–21 — `hits.splice(i, 1)` pulls the next hit into index `i` and the loop's `i++` then skips it, so only every other same-key hit is removed and the key stays half-spent — after a "reset" `allow` still returns `false`, which is the whole point of the method — iterate downward (`for (let i = hits.length - 1; i >= 0; i--)`) or rebuild the array with a filter.
[major] `prune`, line 5 — it only inspects `hits[0]`, so it assumes the array is time-sorted, but `now` is injectable and nothing enforces monotonicity; a backward clock step (common in tests and NTP corrections) leaves expired entries stranded behind newer ones forever — the key stays exhausted and the array grows without bound — prune by scanning for all entries older than `t - windowMs`, or keep per-key buckets pruned from their own timestamps, and document whether `now` must be monotonic.
[major] `allow`, lines 12–13 and 5 — `hits.filter(...)` walks every key's hits on each call while `prune` removes one element per `shift()` (O(n) each), so per-call cost grows with the whole window and a burst is O(n²) on a hot path — store a `Map<key, timestamps[]>` and count/prune only the caller's bucket.
[major] `hits` array, lines 2 and 14 — retention is bounded per key (`limit`) but not across keys, so a limiter keyed by IP or token accumulates up to `limit × distinct keys` live entries in a window and a high-cardinality source grows it without limit — cap tracked keys with an LRU/eviction policy or state explicitly that key cardinality must be bounded by the caller.
[major] `allow` return value, lines 13–15 — a bare boolean gives no `remaining` or `retryAfterMs`, so callers cannot emit `Retry-After` or feedback without guessing, and there is no side-effect-free way to inspect state (a probe records a hit) — return `{ allowed, remaining, retryAfterMs }` and add a non-mutating `peek(key)`.
[minor] `prune` comparison, line 5 — strict `hits[0] < t - windowMs` keeps a hit recorded exactly `windowMs` ago, so the effective window is `windowMs` plus clock granularity and the boundary is unspecified — document inclusive vs exclusive and use `<=` if the window must be exact.
[minor] options destructuring, line 1 — `limit`, `windowMs` and `now` are unvalidated: `limit: 0` silently denies everything, `windowMs: 0` collapses the window to one millisecond, negative/`NaN`/`Infinity` pass straight through, and a `now` returning a non-number corrupts every comparison — validate or clamp at construction and document what `0` means.
[minor] module tests — there are none, and no assertion-accessible state; the injected `now` is the only seam and nothing pins partial reset (see the blocker), per-key isolation, the exact-limit boundary (`n >= limit` allows precisely `limit`), or the line-5 boundary — add tests driven by a manual clock covering those four cases.

[blocker] prune(), hits[0] comparison — `hits[0] < t - windowMs` compares an object `{ key, time }` to a number, which is always false, so nothing is ever pruned — entries never expire, the limit is permanent after `limit` hits per process, and `hits` grows without bound — compare `hits[0].time` instead.
[major] reset(key), for loop — after `splice(i, 1)` the loop still increments `i`, so the entry that slides into index `i` is skipped; consecutive matching entries survive and `reset` leaves the key partly limited — iterate backwards or use `filter` to rebuild the array.
[major] allow(key), `hits.filter(...)` — every call scans the whole global array (all keys) and `shift()` in prune is O(n) per removal, so cost grows with total traffic across all keys, not with this key's hits — keep a per-key queue or Map of timestamps with a head index.
[minor] createLimiter options — `limit`, `windowMs` and `now` are not validated; `limit: 0`, negative, `NaN`, or a non-function `now` fail silently or block everything — validate on construction and throw a clear error.
[minor] prune(t), window boundary — the cutoff is `< t - windowMs`, so a hit exactly `windowMs` old still counts; the window semantics are undocumented and differ from common sliding-window conventions — state the boundary in a comment or doc and test it.
[minor] API surface — `allow` returns only a boolean, with no remaining count or retry-after time, so callers cannot set `Retry-After` headers or back off — return a richer result or add a companion method.
[minor] allow/reset, missing tests — nothing covers window expiry, the per-key separation, the limit boundary, or the reset loop bug that a single test would have caught — add tests with an injected `now` for expiry, multi-key isolation, and reset of consecutive entries.
[nit] reset(key) — the name suggests clearing all state, but it only clears hits for one key and the global `hits` array is still shared; a clearer name or a doc line would prevent misuse.
